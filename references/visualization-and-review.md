# 展示与验收

先读当前 `visualize` 技能的完整说明，使用其内联协议与主题运行时。整图分析的产品界面沿用用户已确认的 [画布模板](canvas-template.md)，包括桌面视口布局和详情独立滚动；不要按通用图表排版重新设计该界面。这里补充电路领域的要求。

## 图上交互

- 保留完整原图、位号、网络名和端口位置。整图模式遵循 [整图模块与大画布](module-canvas.md)：虚线框标识功能，点击展开面板，不因模块选择裁图。需要局部放大时由用户缩放/平移，保留“适应整图”入口和页号、原位号。
- 节点标注显示相对于哪个参考地的电压。差分探针显示两个节点名，而不把差分结果当单端电压。
- 支路电流箭头与模型正向一致，反向电流保留符号；展示动画仅辅助说明，不能用速度代替数值。
- 让用户通过图上节点/元件或可访问的选择控件选择目标，悬停不能成为唯一入口。触摸和键盘也要能查看相同结果。
- 理想导线形成并行回路时，部分线段电流未必唯一。可展示可确定的元件支路电流和约束，不编造“每条导线都有唯一值”。
- 多端口器件标明哪个端口的电流，不能用单一“器件电流”掩盖基极/集电极或各电源脚的不同含义。
- 同一数据状态驱动元件值、节点标签、曲线、计算摘要和告警。用户改值后不可留下上一组结果。

## 控件与模式

- 数值输入与滑块同步，保留工程单位。跨多个数量级时可用对数滑块，但显示真实物理量。
- 使用当前拓扑可支持的范围，解释越界。初始范围可依据已有工作点制定，并标为可调设置而非器件额定范围。
- 正向和反求分别管理可编辑字段，避免目标与结果相互覆盖造成循环更新。
- 传感器物理量变化、元件变化和目标变化是三类不同操作。更新过程应反映用户实际选择。
- 运行求解器失败时不显示上一工况为当前工况。预计算结果只能在有效域内插值；没有覆盖域时提示需重新计算。
- 直流、频域和瞬态页面显示相应工作状态。拖动时间游标不等于改变硬件元件。

## 离线/内联计算

- 内联可视化不能假设能调用本地 CLI 或网络 API。解析小模型可在页面本地重算。
- 复杂 SPICE 可先离线运行一组有边界的参数点再可视化；如需连续任意调参，应实现实际可运行且获授权的引擎集成，或让用户选择参数后请求下一轮分析。
- 无论采用哪条路径，在正文说明实时重算、预计算查看、插值还是定性示意。不要给不工作的“运行仿真”按钮。
- 持久状态只包含有限、校验后的输入。恢复时重新计算，不能信任缓存里的旧电压和电流。

## 最小验收

按当前分析范围选择，不对简单任务强制全面测试：

1. 默认工况与独立计算吻合。
2. 至少改一个真正影响电路的参数，图上电压/电流和结果同步变化。
3. 测一个相关边界：量程端点、目标不可达、输入为空、反向电流、饱和或缺模型。
4. 有反求时，把结果回代到正向模型，检查目标误差和其他约束；无解不会留下上一个“成功”值。
5. 查看实际节点/支路的点击结果，并确认元件与原图 ID 对应。
6. 在常用宽度和窄屏检查标签不重叠、控件能用；深浅色标签与连线可读。

测试产物放工程 `work/`。交付正文只概括实际完成的检查，不把文件存在或静态截图当成功交互的证明。
